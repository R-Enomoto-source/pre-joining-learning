### A. Handling date, time, text, numeric and boolean values（誤答: 2, 6, 7, 12）

#### A-1. 数値リテラル・代入・演算結果の型（問 2）

**仕様の整理**

- 整数リテラルは原則 **`int`**。浮動小数リテラルは原則 **`double`**。
- `byte` / `short` への代入では、**コンパイル時に値が収まる**整数リテラルなら暗黙変換が認められる一方、**範囲外**なら `int` として扱われ、狭い型へはそのままでは代入できない。
- `int` と **`long`（`L` 付きリテラル）** の演算は **`long`** になり、その結果を **`int` 変数**へ代入しようとするとコンパイルエラー。
- **`double` → `float`** は、暗黙変換できない（明示キャストが必要）。

**よくある誤り**

- 「コンパイルエラーになる行」を選ぶ問題で、**int 同士の演算が short に収まる**パターン（解答の選択肢 B）をエラーと誤認する。

**試験で使える手順**

1. リテラルに **`L` / `F` / `D`（暗黙の double）** がないか見る。  
2. 演算の左右で **昇格**（int + long → long 等）を書き出す。  
3. 左辺の型に **代入可能か**だけを判定する。

---

#### A-2. 演算子の優先順位と左結合（問 6）

**仕様の整理**

- `%`、`*`、`/` は加減算より**先**に結合する（教科書の優先順位表どおり）。
- **優先順位が同じ**演算子が並ぶときは、原則として **左から右**へ評価する。

**問 6 の型の追跡（解答どおり）**

式 `(a % b * c) + (a / b)` に `a=100, b=20, c=30` を代入すると:

1. `100 % 20` → **0**（剰余が先。ここで左グループの左端が確定）  
2. `0 * 30` → **0**  
3. `100 / 20` → **5**（整数除算）  
4. `0 + 5` → **5**

**よくある誤り**

- `%` と `*` の順序を逆にする、または `a / b` を先に評価してしまう。

---

#### A-3. カッコ・除算・整数の切り捨て（問 7）

**仕様の整理**

- カッコ `()` は最優先。  
- 減算・加算より **除算が先**。  
- **`int` 同士の除算**は小数部を**切り捨て**た整数になる。

**問 7 の追跡（解答どおり）**

`30 - 12 / (2 * 5) + 1`  

1. `(2 * 5)` → `10`  
2. `12 / 10` → **`1`**（int 除算）  
3. `30 - 1 + 1` を左から → **`30`**

**よくある誤り**

- `12 / 10` を **1.2** のように考えてしまう（**整数型の式では切り捨て**）。

---

#### A-4. ビット演算子とビットパターン（問 12）

**仕様の整理（解答の表どおり）**

- **`&`（AND）**: 両方のビットが 1 の位置だけ 1。  
- **OR（`|` 演算子）**: どちらかが 1 なら 1。  
- **`^`（XOR）**: 片方だけが 1 なら 1。

**問 12 の考え方**

`1011` と `0100` で **結果のビット列がすべて 0** になる演算は **AND のみ**（OR も XOR も 0 にならない）。

**試験でのコツ**

- 選択肢ごとに **2 進 4 桁程度の表**を 1 行書き、下に AND/OR/XOR の結果行を足す。暗算で飛ばさない。

### B. Utilizing Java Object-Oriented Approach（誤答: 8, 9, 10, 11）

#### B-1. 同一性 `==`（問 8）

**用語**

- **同一**: 2 つの参照が **同じインスタンス**を指すこと。  
- **`==`（参照型）**: 同一性の判定。

**問 8の流れ（解答どおり）**

1. `s2 = s1` で **同じ参照**を共有。  
2. `s1 = new Sample(10);` で **`s1` だけ別インスタンス**を指す。  
3. この時点で **`s1 == s2` は false**。

**よくある誤り**

- 「同じクラスのオブジェクトだから true」と混同する（**中身や型ではなく参照先**）。

---

#### B-2. 同値性 `equals` のオーバーライド（問 9）

**仕様の整理**

- **`equals`**: 通常、**同値**（論理的に等しいか）を調べる。  
- 設問のように **「num だけ一致すれば同値」** とオーバーライドされていれば、`name` が違っても **`true`** になり得る。

**`==` との使い分け**

- 参照が同じか → **`==`**  
- 中身が同じか（クラスが定義した意味で）→ **`equals`**

---

#### B-3. オーバーライドとオーバーロード（問 10）

**仕様の整理（解答の核心）**

- `Object` の **`equals` のシグネチャ**は `boolean equals(Object obj)`。  
- 引数を **`equals(Sample obj)`** のように変えるのは **オーバーロード**であり、**`Object` 版を置き換えていない**。  
- `a.equals(b)` の呼び出しでは、**継承した `equals(Object)`** が使われ、デフォルト実装は **`this == obj`** に等しい → **別インスタンスなら false**。

**試験で必ず確認すること**

- メソッド名が同じでも、**引数型がスーパークラスと一致するか**。

---

#### B-4. `equals(null)`（問 11）

**仕様の整理（解答・API 契約どおり）**

- **null 以外の参照 `x` について `x.equals(null)` は `false`**。  
- `Object` の実装は `return (this == obj);` のため、引数 `null` では **`false`**。

**注意**

- よく書くのは **`Objects.equals(a, b)`** や **`"literal".equals(var)`** のように **NPE を避ける側**から呼ぶパターン。試験では **契約の真偽**が問われることが多い。

### C. Controlling Program Flow（誤答: 14, 15, 16, 17, 18, 19, 20, 22, 26, 27, 28, 40, 43）

#### C-1. `if` / `else` と中カッコ省略（問 14, 15, 16）

**仕様の整理（言語共通の鉄則）**

- `{ }` を省略したとき、**`if` / `else` に付随するのは「直後の 1 文」だけ**。  
- **2 文目以降は条件と無関係**（インデントで誤魔化さない）。

**問 16 の読み方（解答どおり）**

- `if (num < 10) ... else ...` のあとに続く **`if (num == 10)` は別の文**。  
- 最初の if-else で **B**、続く if で **C** が出るパターンが正解側の選択肢に対応する。

**対策**

- 試験用に、**一時的にすべての `if`/`else`/`for`/`while`/`do` に `{}` を脳内補完**してから実行順を数える。

---

#### C-2. `switch` 条件式の型（問 17）

**仕様の整理（解答の列挙どおり）**

条件式に使える代表:

- `char`, `byte`, `short`, `int` とラッパー `Character`, `Byte`, `Short`, `Integer`  
- **`String`**、**列挙型（enum）**

**含まれない例（解答が明示）**

- **`long`**、**`boolean`**、**`float` / `double`** など。

**よくある誤り**

- 「整数なら全部 OK」と **`long`** を含めてしまう。

---

#### C-3. `case` ラベルに書ける式（問 18）

**仕様の整理（解答どおり）**

- **定数**であること、または **コンパイル時に値が確定する**こと。  
- **変数**は実行中に変わり得るため **`case` 値にできない**。  
- 条件式の型と **互換のないリテラル**を `case` に書くのもコンパイルエラー。

**試験のチェック**

- `case` の右が **リテラル／final 定数／定数式**か、変数でないかを見る。

---

#### C-4. `switch` 文のフォールスルー（問 19, 20）

**仕様の整理**

- **`break` がない**と、一致した `case` のあと **下の `case` / `default` へ流れる**（**フォールスルー**）。  
- **`default` は最後でなくてもよい**。`default` にも **`break` がなければ**その下の `case` に流れる。

**問 19・20 の読み方**

- **表示順**を「上から順に積む」イメージで追う。`break` で初めて `switch` 全体が終わる。

---

#### C-5. `switch` 式と網羅（問 22）

**仕様の整理（解答どおり）**

- **`switch` 式**は **式として値を返す**ため、**すべての入力値がどこかの arm に落ちる**必要がある（網羅）。  
- **`int` の全範囲**を少数の `case` で埋めきれないとき、**`default` がないとコンパイルエラー**になり得る。  
- 従来の **`switch` 文**では `default` 省略が許されるケースもあるが、**式では厳しい**、という対比が試験の狙いになりやすい。

---

#### C-6. `do`-`while` の構文と意味（問 26）

**仕様の整理**

- **`do { } while (条件);`** — **`while` の後ろはセミコロン必須**。  
- **`do` の直後に条件を書く**のは構文エラー。  
- **本体を一度は実行**してから条件判定する（`while` との違い）。

---

#### C-7. `do`-`while` と中カッコ省略（問 27）

**仕様の整理（解答どおり）**

- `do` と `while` の間に **文が 2 つ以上**あるのに **`{ }` がない**と **コンパイルエラー**。  
- 繰り返し対象は **`do` の直後の 1 文だけ**。

---

#### C-8. `for` の初期化文（問 28）

**仕様の整理（解答どおり）**

- 初期化文で **カンマ区切りの複数宣言**は **`同じ型` のみ**可。  
- **`int` と `long` を同時に宣言**などは **コンパイルエラー**。

---

#### C-9. `break` と二重ループ（問 40）

**仕様の整理（解答どおり）**

- **`break` は「最も内側の」その時点の `switch` またはループ**だけを抜ける。  
- **外側のループは継続**する。二重ループでは **表示回数や組み合わせを表にする**と安全。

---

#### C-10. ラベル付き `continue` / `break`（問 43）

**仕様の整理（解答どおり）**

- **`continue ラベル;`**: そのラベルが指す **外側ループの次の反復**へ。  
- **`break ラベル;`**: そのラベルが付いた **文／ループの直後**へ（内側ループだけ抜ける `break` とは異なる）。  
- 設問のように **偶数 `i` で内側全体をスキップ**し、**`j` が一定以上で内側だけ抜ける**、が重なるときは **表で `i`×`j` を埋める**のが確実。

### D. Working with Arrays and Collections（配列のみ／誤答: 33, 34）

#### D-1. ジグザグ配列と内側の終端（問 33）

**仕様の整理**

- 行 `i` の要素数は **`array[i].length`**。内側ループは通常 **`j = 0; j < array[i].length; j++`** の形が基本。  
- 固定の **`j < 2`** などは、行ごとの長さと合わないと **合計値がずれる**か **範囲外アクセス**になる。

**対策**

- 外側 `i` ごとに **「その行の長さ」**を書き、内側で回す添字の上限を照合する。

---

#### D-2. `length` は「何の長さか」（問 34）

**仕様の整理（解答どおり）**

- **2 次元配列 `matrix` に対する `matrix.length`** は **1 次元目（行数）**。  
- **`matrix[i].length`** が **その行の列数**。

**問 34 の読み方**

- 外側・内側ループの条件が **`length`（1 次元目）だけ**を見ているのか、**各行の `.length`** も見ているのかを分離する。

---

### E. メタ：複数選択の完全一致（問 2, 17, 18）

**試験運用上の弱点**

- 正解が **複数肢**のとき、**多い／少ない／1 つ違い**はすべて不正解になりやすい。

**対策**

- 設問文の **「いくつ選べ」**と、自分のマークした **個数・集合**を最後に必ず照合する。
