### 1. 仕様に基づいて断定する（NULL の例）

Java には C 言語のような特別なキーワード `NULL` は存在せず、参照が何も指していない状態は `null` というリテラルで表します。  
選択肢に「Java には NULL がある」といった文があれば、**言語仕様と違うので迷わず誤り**と判断できます。

- **ポイント**
  - 「どちらとも言えそう」と感じたら、仕様で白黒つく部分を探す。
  - 曖昧な直感より、仕様に書いてあるかどうかを優先する。

### 2. static フィールドと static メソッド

**static フィールド**

- インスタンスではなく「クラスそのもの」に属します。
- そのため、インスタンスを作らなくても `クラス名.フィールド名` でアクセスできます。

```java
class Counter {
    static int count = 0;
}

Counter.count = 10; // インスタンス new Counter() は不要
```

**static メソッド**

- クラスに属するメソッドで、「インスタンスに紐づく情報（非 static フィールド）」は直接扱えません。
- **static メソッドの中からアクセスできるのは static メンバだけ**です。

```java
class Sample {
    int num;          // 非 static フィールド
    static int sNum;  // static フィールド

    static void foo() {
        // num = 1;     // コンパイルエラー：インスタンスフィールド
        sNum = 1;       // OK：static フィールド
    }

    void bar() {
        num = 1;   // OK
        sNum = 2;  // OK：非 static から static は参照できる
    }
}
```

- **整理**
  - 「外から呼べる／呼べない」ではなく、「static の『中から』何にアクセスできるか」を意識する。
  - フィールドに値を入れるときも、「static ならクラス名から直接アクセスできる」を思い出す。

### 3. エラーが発生する「行」を特定する考え方

**void メソッドの `return;`**

```java
void test() {
    return;          // これは OK
    System.out.println("ここには到達しない"); // ここが「到達不能コード」でエラー
}
```

- `void` メソッドにおける `return;` 自体は正しい文です。
- エラーになるのは、その **後に書かれた絶対に実行されないコード** です。

**あいまいなメソッド呼び出し**

```java
void foo(int x) { }
void foo(long x) { }

void main() {
    foo(10); // ここで「どちらを呼ぶかあいまい」と判断されれば、この行がエラー
}
```

- 「どちらのメソッドか判別できない」という理由は正しくても、
- **エラーとして報告される行は「呼び出しを書いている行」**です。
- 定義側（メソッド宣言の行）ではなく、呼び出し側にエラーが付くと意識しておくと、選択肢で迷いにくくなります。

### 4. 初期化子とコンストラクタの実行順 / this(...) の位置

**初期化子の実行順**

```java
class Sample {
    static { System.out.println("static 初期化子"); }

    { System.out.println("インスタンス初期化子"); }

    Sample() {
        System.out.println("コンストラクタ");
    }
}
```

- インスタンス関連では、**インスタンス初期化子 → コンストラクタ**の順に実行されます。
- 「A → B なのか、B → A なのか」を考える問題では、**初期化子が先**と覚えておきます。

**this(...) 呼び出しの位置**

```java
class Sample {
    Sample() {
        // System.out.println("before"); // ここに何か書くと、その後の this(...) はエラー
        this("B"); // コンストラクタの先頭でなければならない
    }

    Sample(String s) {
        System.out.println(s);
    }
}
```

- `this(...)` は **コンストラクタの最初の文**でないといけません。
- その前に `System.out.println` などの文があると、コンパイルエラーになります。
- 実行結果を考える前に、「そもそもコンパイルが通るか？」をチェックする癖をつけるとミスが減ります。

### 5. コンストラクタとメソッドの違い・デフォルトコンストラクタ

```java
class Sample {
    void Sample() { } // これは「メソッド」。戻り値型 void が付いている

    // 引数なしコンストラクタは定義されていない
}

new Sample(); // コンパイルエラー（引数なしコンストラクタが存在しない）
```

- **コンストラクタ**には戻り値型を書きません（`void` も含めて、型を書いた時点でコンストラクタではない）。
- クラスに **1つもコンストラクタを定義していないときだけ**、コンパイラがデフォルトコンストラクタ（引数なし）を自動で追加します。
- 何らかのコンストラクタや「コンストラクタ風メソッド」を書いたときは、「デフォルトがまだあるか？」を確認するようにします。

### 6. 参照型引数とプリミティブ引数

```java
class Sample {
    int num;
}

void change(Sample s) {
    s.num = 20; // 引数 s が指すインスタンスの中身を書き換える
}

void main() {
    Sample s = new Sample();
    s.num = 10;
    change(s);
    // s.num は 20 になる
}
```

- Java では**すべて値渡し**ですが、参照型の場合は「参照（アドレス）の値」を渡します。
- 渡された参照はコピーされますが、**指しているインスタンスは同じ**なので、そのインスタンスのフィールドを変えると呼び出し元にも反映されます。
- 一方、`int` や `double` などプリミティブは値そのものをコピーするので、メソッド内で変えても呼び出し元には影響しません。

### 7. パターン変数のスコープと「コンパイルが通るか」

```java
if (obj instanceof String s) {
    System.out.println(s.length()); // s はここで有効
} else {
    // s はここでは使えない（未定義）
}
```

- `instanceof` のパターン変数（上の `s`）は、**if ブロックの中だけ**有効です。
- else ブロックで同じ名前 `s` を使おうとすると、コンパイルエラーになります。
- 「BBBB と表示される」など結果だけを追う前に、**そもそもコンパイルが通るコードか**を先に確認するのが大事です。

### 8. 「誤っているものを選べ」とレコードの問題の解き方

- 「誤っているものを 1 つ選べ」という問題では、
  - **誤りを 1 つに特定する**
  - 他の選択肢は「すべて正しい説明」と確認する
- レコードに関する代表的なポイント：

  - `toString`, `hashCode`, `equals` が自動生成されるのは**正しい説明**。
  - レコードは `final` なので、**レコードを継承したサブクラスは作れない** → ここが誤りかどうかを見抜く。

### 9. トップレベルレコードの修飾子とフィールド制約

- トップレベルのレコードに付けられる修飾子は **`public` と修飾子なし**だけです。
  - `private` はインナークラス用と覚えると整理しやすいです。
- レコードで **宣言できないフィールド**：
  - **static でないフィールドの明示的な追加**（コンポーネント以外に非 static フィールドを足すこと）は不可。
- 一方で、**static フィールドは宣言できます**。  
  「static はダメ」とまとめて覚えず、「**static でない追加フィールドがダメ**」と区別します。

### 10. 代替コンストラクタとコンパクトコンストラクタ

- 代替コンストラクタ（追加のコンストラクタ）には次のような要件があります：
  - 標準コンストラクタと **同じ引数**を受け取るか、
  - すべてのフィールドを**最終的に初期化する**必要がある。
- レコードに **非 static フィールドを追加して初期化するような代替コンストラクタ**は許されません。
- コンパクトコンストラクタでは、**`this.フィールド` を直接使えない**といった細かい制約もあります。
  - ここは公式解説のコードを何度か書き写して、どこでエラーになるかを体で覚えるのがおすすめです。

### 11. float の戻り値と受け取る型（複数選択）

```java
float f() { return 1.0f; }

void main() {
    float a = f();  // OK
    double b = f(); // OK（float → double への拡大変換）
}
```

- 戻り値型が `float` のとき、結果を受け取れる変数の型は
  - `float`（同じ型）
  - `double`（互換性のある拡大変換）
- 複数選択問題では、**どちらも正解になり得る**ため、「B だけでなく C も選ぶ」必要があります。

### 12. どのインスタンスのフィールドが変わるかを追う

```java
class Sample {
    int num;
}

void main() {
    Sample a = new Sample();
    Sample b = new Sample();
    a.num = 10;
    b.num = 20;

    Sample x = a;
    x.num = 30;
    // このとき変わるのは a.num（と x.num）で、b.num は変わらない
}
```

- 変数名ではなく、「**どの new したオブジェクトを指しているか**」を意識して追います。
- a と b は別々のインスタンスなので、それぞれの `num` がどう変わるかを図で書き出すと理解しやすくなります。

### 13. パッケージとアクセス修飾子の本質

- package-private（修飾子なし）のフィールドは、
  - 同じパッケージ内のクラスからはアクセス可能。
  - 別パッケージのサブクラスからはアクセスできません。
- 「`super.` を付ければ見える」という問題ではなく、**パッケージと修飾子の組み合わせで決まるルール**です。
- protected も「同一パッケージ」か「サブクラス」かでアクセス可能範囲が変わるので、表にして整理しておくと安心です。

### 14. レコードのフィールドと getter（value と value()）

```java
public record Data(String value) { }

void main() {
    Data data = new Data("hello");
    // data.value;   // フィールドは private なので直接アクセス不可
    String s = data.value(); // こちらの getter は OK
}
```

- レコードのコンポーネントは private フィールドとして保持され、同名の getter メソッド（ここでは `value()`）が自動生成されます。
- 「`value` はメソッドではないから A は誤り」という考え方ではなく、
  - **フィールドは private なので `data.value` は不可**
  - **getter メソッド `value()` が正しいアクセス方法**
  と整理すると、正解の選択肢ときれいに一致します。
