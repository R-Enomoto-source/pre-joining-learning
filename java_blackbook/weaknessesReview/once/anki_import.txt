# 基本カード (Basic)
abstractが付いたクラスは、newで直接インスタンス化できるか？	できない	Java_Ch5_抽象
抽象クラスとは、どのような前提で使うクラスか？	サブクラスを作って使う前提の、単体では不完全なクラス	Java_Ch5_抽象
抽象メソッドの本体（{}の中身）はどうなっているか？	ない（中身なし）	Java_Ch5_抽象
抽象メソッドの実際の処理は、どこで実装する必要があるか？	サブクラスが必ず実装する	Java_Ch5_抽象
「A a = new B();」のとき、変数の型はどちらか？	A	Java_Ch5_ポリモ
「A a = new B();」のとき、実際のインスタンスの型はどちらか？	B	Java_Ch5_ポリモ
メソッド呼び出しで、どの型のメソッドが実行されるか決めるのはどちらか（変数の型／実際のインスタンスの型）？	実際のインスタンスの型	Java_Ch5_ポリモ
フィールド参照で、どの型のフィールドが使われるか決めるのはどちらか（変数の型／実際のインスタンスの型）？	変数の型	Java_Ch5_ポリモ
親子で同名のフィールドがあるとき、変数の型がAで「b.val」と書いたらどのクラスのvalを参照するか？	Aのval	Java_Ch5_ポリモ
親子で同名のnameフィールドがあり、child.getName()でthis.nameを返すメソッドがParent側にあるとき、参照されるのはどちらのnameか？	Parent側のname	Java_Ch5_ポリモ
インタフェースのメソッド宣言に何も修飾子を書かないと、自動的に何になるか？	public abstract	Java_Ch5_インタフェース
インタフェースで、本体（実装）を持てるメソッドの種類は？	defaultメソッドとstaticメソッド	Java_Ch5_インタフェース
defaultメソッドは、どのような実装を持たせたいときに使うか？	標準的な実装	Java_Ch5_インタフェース
インタフェースで、Object由来のメソッド（例：toString）をdefaultメソッドとしてオーバーライドできるか？	できない（コンパイルエラー）	Java_Ch5_インタフェース
「インタフェース名.super.メソッド()」は、そのインタフェースを直接継承している型からしか呼べるか、間接的でも呼べるか？	直接継承／実装している型からしか呼べない	Java_Ch5_インタフェース
A→B→Cと継承関係が2段以上あるとき、CからA.super.sample()を直接呼べるか？	呼べない	Java_Ch5_インタフェース
インタフェースのprivateメソッドの目的は何か？	defaultメソッドやstaticメソッドの共通処理をまとめるため	Java_Ch5_インタフェース
インタフェースのprivateメソッドに、本体（{}）は必要か？	必ず必要	Java_Ch5_インタフェース
抽象メソッドをprivateにできるか（インタフェース内）？	できない	Java_Ch5_インタフェース
インタフェースはnewでインスタンス化できるか？	できない	Java_Ch5_代入互換
配列の要素型と、実際に入れるインスタンスの型の間には、どのような関係が必要か？	代入可能な関係	Java_Ch5_代入互換
子クラス型を親クラス型の変数に代入するキャストを何というか？	アップキャスト	Java_Ch5_キャスト
アップキャスト（子→親）には、明示的なキャストが必要か？	不要（自動でOK）	Java_Ch5_キャスト
親クラス型の変数を子クラス型に代入するキャストを何というか？	ダウンキャスト	Java_Ch5_キャスト
ダウンキャスト（親→子）には、明示的なキャストが必要か？	必要	Java_Ch5_キャスト
「A a = new A(); B b = (B)a;」のように、実際のインスタンスがキャスト先と互換性がないときに実行時に発生する例外は？	ClassCastException	Java_Ch5_キャスト
キャスト式を書くとコンパイルは通るが、実際のインスタンスが互換性を持たないとどうなるか？	実行時に例外（ClassCastException）	Java_Ch5_キャスト
sealedクラスで、継承できるクラスを限定するキーワードは？	permits	Java_Ch5_sealed
sealedクラスを継承するサブクラスは、final／sealed／non-sealedのどれかが必須か？	必須（何も付けないとコンパイルエラー）	Java_Ch5_sealed
sealedクラスのサブクラスで「これ以上継承させない」とき付ける修飾子は？	final	Java_Ch5_sealed
sealedクラスのサブクラスで「さらにpermitsで継承先を限定する」とき付ける修飾子は？	sealed	Java_Ch5_sealed
sealedクラスのサブクラスで「そこから先は自由に継承してよい」とき付ける修飾子は？	non-sealed	Java_Ch5_sealed
sealedインタフェースを実装するクラスにも、final／sealed／non-sealedのどれかが必須か？	必須	Java_Ch5_sealed
sealedは、誰が継承（実装）してよいかをどこで限定する仕組みか？	親側で限定する	Java_Ch5_sealed
オーバーライドで、メソッド名・引数の型・数・順番は元とどうある必要があるか？	同じ（シグニチャが同じ）	Java_Ch5_オーバーライド
オーバーライドの戻り値型は、元と同じかどうでなければならないか？	同じか、そのサブクラス型（共変戻り値）	Java_Ch5_オーバーライド
オーバーライドで、アクセス修飾子はprotectedからpublicに変更できるか？	できる（より緩い方向のみ可）	Java_Ch5_オーバーライド
オーバーライドで、アクセス修飾子はprotectedからprivateに変更できるか？	できない	Java_Ch5_オーバーライド
親クラスのコンストラクタと子クラスのコンストラクタ、どちらが先に実行されるか？	親クラスのコンストラクタが先	Java_Ch5_コンストラクタ
子クラスのコンストラクタの先頭には、暗黙に何が挿入されるか？	super();	Java_Ch5_コンストラクタ
同じクラス内の別コンストラクタを呼びたいときに使う記法は？	this(...)	Java_Ch5_コンストラクタ
フィールドと引数が同名のとき、フィールドを明示的に参照するには何を付けるか？	this.	Java_Ch5_コンストラクタ

# 穴埋めカード (Cloze)
抽象クラスは「そのクラス単体では不完全で、必ず{{c1::サブクラス}}を作って使う前提」のクラスである。	Java_Ch5_抽象
抽象メソッドが呼ばれたとき、実際に実行されるのは{{c1::サブクラス}}が実装したメソッドである。	Java_Ch5_抽象
オブジェクト指向では、{{c1::変数の型}}（宣言時に書くもの）と{{c2::実際のインスタンスの型}}（newしたクラス）を分けて考える。	Java_Ch5_ポリモ
フィールド参照は{{c1::変数の型}}のフィールドが使われ、動的ディスパッチされない。	Java_Ch5_ポリモ
変数の型がAで「b = new B()」のとき、b.valは{{c1::A}}のvalを参照し、Bのvalは見ない。	Java_Ch5_ポリモ
child.nameに代入すると{{c1::Child}}側のnameに入り、ParentのgetName()内のthis.nameは{{c2::Parent}}側のnameを参照する。	Java_Ch5_ポリモ
インタフェースには抽象メソッド、{{c1::default}}メソッド、{{c2::static}}メソッドを書ける。	Java_Ch5_インタフェース
Aを実装したクラスは、defaultメソッドを{{c1::オーバーライドしなくても}}そのまま使える。	Java_Ch5_インタフェース
「インタフェース名.super.メソッド()」は、そのインタフェースを{{c1::直接}}継承しているインタフェース、または{{c1::直接}}implementsしているクラスからだけ使える。	Java_Ch5_インタフェース
A[] array = { new A() } は、インタフェースの{{c1::インスタンス化}}なのでコンパイルエラーになる。	Java_Ch5_代入互換
Aと無関係な型DのインスタンスをA型配列に入れようとすると{{c1::コンパイルエラー}}になる。	Java_Ch5_代入互換
コンパイラは継承関係があればキャスト式をOKとみなすが、実際のインスタンスが互換性を持たないと{{c1::実行時}}にClassCastExceptionが発生する。	Java_Ch5_キャスト
sealed class Sample permits A, B と書くと、Sampleを継承できるのは{{c1::AとB}}に限定される。	Java_Ch5_sealed
sealedのサブクラスには、継承の方針を示す修飾子（{{c1::final}}／{{c1::sealed}}／{{c1::non-sealed}}）が必須である。	Java_Ch5_sealed
オーバーライドでは、アクセス修飾子は同じか、より「{{c1::緩い}}」ものだけに変更可能である。	Java_Ch5_オーバーライド
子クラスのコンストラクタの先頭には、暗黙に{{c1::super()}}が挿入され、親のコンストラクタが先に動く。	Java_Ch5_コンストラクタ
