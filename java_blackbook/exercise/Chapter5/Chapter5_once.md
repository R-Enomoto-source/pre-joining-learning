2.  C
    ABDは説明が間違っているため。正しい説明がCだけであるため。アクセス修飾子がつかないデフォルトのフィールドは同一パッケージのみアクセス可能である。アクセス修飾子がprivateであるメソッドは、同クラス内でのみアクセスできる。protectedなメソッドは、同一パッケージまたは継承先のサブクラスがアクセスできる。

4.  A
    プログラムを正しく動作させるにはAのインタフェースでデフォルトメソッドにすることが必要であり、それ以外は正しくないため。Bはインタフェースは抽象メソッドがないとインタフェースでなくなるため、Cは、このままならコンパイルエラーになり、例外はスローされないため。Dはこのままではコンパイルエラーになり、正しく実行されないため。
5.  A
    Overrideできない所で@Overrideを書いているため、コンパイルエラーになるのではないか。コンパイルエラーコンパイルエラーにならないならC。
    @OverrideがOverrideする必要のないクラスで、あるいはメソッドの直前に書くことがコンパイルエラーになるのかどうかが分からない。@Overrideの運用ルール、文法が分からない。
6.  A
    BはAのデフォルトメソッドを継承しているため、記述がなくても暗黙的にＡのdefaultvoidsample()のメソッドを利用可能である。そして、BクラスはCクラスの一つ内側であるため、superでアクセスできる。BCDは間違っているため。BはAが1番内側でそれより内側は存在しないため間違っている。CDは存在しない書き方であるため間違っている。
7.  C
    どちらのデフォルトメソッドを使用するのかコンパイラが分からないため、コンパイルエラーになると思われるため。
    new Main().test();この書き方ができるとは知らなかった。デフォルトメソッドが定義されているインタフェースを多重継承する際には、どちらを使うのか明示しなければならないと思う。どのように明示すればよいのか。一つはオーバーライドがあると思われる。A.test()やB.test()でもいけるのかはわからない。
8.  ACD
    Aは抽象クラスのインスタンスを生成できてしまうと、定義されていないメソッドが呼び出されたときに必ずコンパイルエラーになってしまうため。Cはpublicで修飾しているのであれば想定し得る挙動であるため。Dは抽象クラスは抽象クラスを継承できると知識で知っているため。
    Bはオーバーライド出来なければ抽象クラスを作成する意味がなくなってしまうから。Eは例えば、抽象クラスが抽象クラスを継承するなどしたときに、実装せずに継承することが考えられるため。

    protected abstract void test();この書き方が許されているのか、分からない。許されていそうではある。抽象クラスが処理を記述しないメソッドを作ることで機能しているので、{}がなくてもよさそうではある。

    そうすると、implementsの文法規則がよくわからない。
