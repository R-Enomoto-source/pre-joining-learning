# `intern()` メソッドで `true` になる理由（初学者向け解説）

## 1. まずは前提：`String` には2種類の作り方がある

Javaで文字列を作る方法は大きく分けて2つあります。

```java
String a = "hello";              // (1) 文字列リテラル
String b = new String("hello");  // (2) new で生成
```

この2つは**メモリ上の置き場所が違います**。

---

## 2. メモリの中をのぞいてみよう

Javaのメモリには「ヒープ領域」があり、その中に **String Pool（文字列プール、別名：String Constant Pool）** という特別な部屋があります。

```
┌─────────────────── ヒープ領域 ───────────────────┐
│                                                  │
│  ┌─── String Pool ───┐                           │
│  │                   │                           │
│  │   "hello"  ←(A)   │     new String("hello")   │
│  │                   │         ↑                 │
│  └───────────────────┘        (B)                │
│                                                  │
│                           new String("hello")    │
│                               ↑                  │
│                              (C)                 │
└──────────────────────────────────────────────────┘
```

- **リテラル** `"hello"` → String Pool に **1つだけ** 作られる（同じ文字列なら使い回される）
- **`new String("hello")`** → ヒープ領域に **毎回新しいオブジェクト** が作られる

---

## 3. なぜ `==` だと `false` になるのか

```java
String str1 = new String("hello");
String str2 = new String("hello");
System.out.println(str1 == str2);  // false
```

`==` 演算子は、参照型（オブジェクト）の場合 **「同じ場所を指しているか？」** を比較します。

- `str1` → ヒープの (B) を指している
- `str2` → ヒープの (C) を指している

**指し示す場所が違う**ので `false` になります。

> ※ `equals()` は中身（文字の並び）を比較するので `true` になります。

---

## 4. `intern()` は何をしているのか

`intern()` メソッドの動きは、たった一文で説明できます。

> **「このオブジェクトと同じ文字列が String Pool にある？  
> あれば、その参照を返す。なければ Pool に登録してから返す」**

つまり、

```java
str1.intern()  // → Pool 内の "hello" (A) の参照を返す
str2.intern()  // → Pool 内の "hello" (A) の参照を返す
```

**両方とも同じ (A) を指す**ことになります。

```
str1.intern() ──┐
                ├──→  String Pool の "hello" (A)
str2.intern() ──┘
```

---

## 5. だから `==` で比較すると `true`

```java
System.out.println(str1.intern() == str2.intern());  // true
```

- `str1.intern()` の戻り値 = Pool の (A) への参照
- `str2.intern()` の戻り値 = Pool の (A) への参照
- **同じ場所を指している** → `==` は `true`

---

## 6. まとめ表

| 比較式 | 結果 | 理由 |
|--------|------|------|
| `str1 == str2` | `false` | ヒープ上の別オブジェクトを指しているから |
| `str1.equals(str2)` | `true` | 中身の文字列が同じだから |
| `str1.intern() == str2.intern()` | `true` | どちらも String Pool 内の同じ参照を返すから |

---

## 7. ひとことで覚える

> **`intern()` は「文字列プールの中の代表選手の参照」を返してくれるメソッド**  
> だから、同じ文字列なら必ず同じ参照になり、`==` でも `true` になる。

---

## 補足：なぜこんな仕組みがあるの？

文字列はプログラム中で大量に使われます。同じ `"hello"` が何百個もメモリにあったら無駄ですよね。そこで Java は **「同じ文字列リテラルは1つだけ持って使い回す」** という最適化（インターン化）を行っています。`intern()` はこの仕組みを `new` で作った文字列にも適用するためのメソッドなのです。

# 空の配列を `println` で表示するとハッシュコードが出る理由（初学者向け解説）

## 1. まず結論を一言で

> **配列にも `toString()` メソッドがあるけれど、それは `Object` クラスから受け継いだ「中身を見ないバージョン」だから、文字列ではなく "クラス名 + ハッシュコード" が表示されるのです。**

---

## 2. `println` の正体

```java
System.out.println(何か);
```

`println` はとても親切なメソッドで、引数の型に応じて動きを変えます。

| 引数の型 | 動作 |
|----------|------|
| `int`, `double` などの基本型 | そのまま数値を文字に変換して表示 |
| `String` | そのまま文字列を表示 |
| **オブジェクトへの参照**（配列含む） | **そのオブジェクトの `toString()` を呼んで、戻ってきた文字列を表示** |

つまり、

```java
int[] array = new int[0];
System.out.println(array);
```

は内部的にこう動いています。

```java
System.out.println(array.toString());
```

---

## 3. ところで `toString()` ってどこから来たの？

Javaの **すべてのクラス** は、見えないところで `Object` クラスを継承しています。配列も例外ではありません。

```
        Object  ← すべての親
          ↑
          │ (継承)
          │
      int[] 配列
```

`Object` クラスには `toString()` というメソッドが最初から用意されていて、その中身はこうなっています。

```java
public String toString() {
    return getClass().getName() + "@" + Integer.toHexString(hashCode());
}
```

これが何を返すかというと…

| 部品 | 意味 | 例 |
|------|------|-----|
| `getClass().getName()` | このオブジェクトのクラス名 | `[I`（int配列の意味） |
| `"@"` | 区切り文字 | `@` |
| `Integer.toHexString(hashCode())` | ハッシュコードを16進数の文字列に変換したもの | `1540e19d` |

つなげると、こんな感じの文字列になります。

```
[I@1540e19d
```

---

## 4. なぜ「配列の中身」が表示されないのか？

ここがポイントです。

`String` クラスや `Integer` クラスは、`Object` から受け継いだ `toString()` を **自分用に書き直して（オーバーライドして）** います。だから中身がきれいに表示されます。

```java
String s = "hello";
System.out.println(s);   // → hello （String が toString を書き直しているため）
```

しかし、**配列クラスは `toString()` を書き直していません**。だから `Object` の素のままの `toString()` が呼ばれてしまい、結果として「クラス名 + @ + ハッシュコード」が表示されるのです。

```java
int[] array = new int[0];
System.out.println(array);   // → [I@1540e19d のような表示
```

これは「中身が空だから」ではなく、**要素があってもなくても同じ結果**になります。

```java
int[] array2 = {1, 2, 3};
System.out.println(array2);  // → [I@xxxxxxxx （やはりハッシュコード）
```

---

## 5. クラス名が `[I` ってどういうこと？

配列のクラス名はちょっと変わった表記になります。

| 表記 | 意味 |
|------|------|
| `[I` | `int` の配列 |
| `[J` | `long` の配列 |
| `[D` | `double` の配列 |
| `[Ljava.lang.String;` | `String` の配列 |

先頭の `[` が「配列ですよ」という印で、後ろの記号が要素の型を表しています。

---

## 6. ハッシュコードって何？

ざっくり言うと **「そのオブジェクトを見分けるための番号」** です。

- 同じオブジェクトを指していれば同じ番号
- 別のオブジェクトなら（基本的に）違う番号

人間で言えばマイナンバーのようなもので、`Object` クラスはこれを使って「このオブジェクトはどれかな？」を区別しています。`toString()` がこの番号を表示に混ぜているのは、**「中身を表示する方法を用意していないので、せめてどのオブジェクトかが分かる識別子を返しておくね」** という保険のような仕組みです。

---

## 7. じゃあ配列の中身を見たいときは？

`java.util.Arrays` クラスの `toString()` を使います。

```java
import java.util.Arrays;

int[] array = new int[0];
System.out.println(Arrays.toString(array));   // → []

int[] array2 = {1, 2, 3};
System.out.println(Arrays.toString(array2));  // → [1, 2, 3]
```

`Arrays.toString()` は配列専用に作られた表示メソッドで、要素を `[ , , ]` の形できれいに表示してくれます。

---

## 8. 全体の流れをまとめ図に

```
System.out.println(array);
            │
            ▼
   array.toString() を呼ぶ
            │
            ▼
   配列は toString を書き直していない
            │
            ▼
   親クラス Object の toString が呼ばれる
            │
            ▼
   "クラス名 + @ + ハッシュコード16進数" を返す
            │
            ▼
   [I@1540e19d のような文字列が表示される
```

---

## 9. ひとことで覚える

> **配列は `toString()` をサボって（オーバーライドせずに）親の `Object` のまま使っているので、中身ではなく「身分証明書（クラス名＋ハッシュコード）」が表示される。**

中身を見たければ `Arrays.toString(配列)` を使う、と覚えておきましょう。

# 配列の宣言の原則（初学者向け解説）

## 1. まず一番大事な原則を一言で

> **「`[]`（大カッコ）の数 = 配列の次元数」  
> そして、`[]` は "型の後ろ" にも "変数名の後ろ" にも書ける。**

この2つさえ覚えれば、配列の宣言で迷うことはなくなります。

---

## 2. 配列宣言の基本パターン

Javaで配列を宣言する方法は、書く位置に応じて **2通り** あります。

### パターンA：型の後ろに `[]` を書く（推奨スタイル）

```java
int[] array;
```

「`int` の配列型」という意味で、**型を見ただけで配列だと分かる** のがメリットです。Javaらしい書き方とされています。

### パターンB：変数名の後ろに `[]` を書く（C言語スタイル）

```java
int array[];
```

C言語やC++から来た人のために用意されている書き方です。動作はパターンAとまったく同じです。

> **どちらを書いてもコンパイルは通り、動きも同じ**。ただし、現代のJavaでは **パターンA（型の後ろ）が推奨** されています。

---

## 3. なぜ2通りもあるの？

これは歴史的な事情です。

- C言語やC++では「変数名の後ろに `[]`」が伝統的な書き方
- それらの言語からJavaに移ってくる技術者が混乱しないように、Javaでは **両方の書き方を許容** している

つまり「親切心」で2通り用意されている、というわけです。

---

## 4. 多次元配列も同じ原則

「配列の中に配列が入っている」ものを **多次元配列** と呼びます。

```
2次元配列のイメージ：
 [外側]
  ├─ [内側0] → 0, 1, 2
  ├─ [内側1] → 0, 1, 2
  └─ [内側2] → 0, 1, 2
```

宣言するときは、**次元の数だけ `[]` を書く** だけ。

| 次元 | 書き方の例 |
|------|------------|
| 1次元 | `int[] a;` |
| 2次元 | `int[][] a;` |
| 3次元 | `int[][][] a;` |

---

## 5. 多次元配列でも `[]` の位置は自由

ここがちょっと面白いところです。**`[]` を型の後ろと変数名の後ろに分けて書いてもOK** なのです。

### 2次元配列の宣言例（全部正しい）

```java
int[][] a;     // 型の後ろにまとめて
int a[][];     // 変数名の後ろにまとめて
int[] a[];     // 分けて書く（型の後ろに1つ、変数名の後ろに1つ）
```

### 3次元配列の宣言例（全部正しい）

```java
int[][][] a;   // 型の後ろにまとめて
int a[][][];   // 変数名の後ろにまとめて
int[][] a[];   // 分けて書く（型の後ろに2つ、変数名の後ろに1つ）
int[] a[][];   // 分けて書く（型の後ろに1つ、変数名の後ろに2つ）
```

> **ルールはシンプル：「型の後ろの `[]` の数」＋「変数名の後ろの `[]` の数」＝ 全体の次元数**

---

## 6. 一覧表でまとめ

| 宣言 | 次元数 | 意味 | 推奨度 |
|------|--------|------|--------|
| `int[] a;` | 1次元 | int の配列 | ◎ |
| `int a[];` | 1次元 | int の配列（C風） | △ |
| `int[][] a;` | 2次元 | int の2次元配列 | ◎ |
| `int a[][];` | 2次元 | 同上（C風） | △ |
| `int[] a[];` | 2次元 | 同上（混在スタイル） | × 読みにくい |
| `int[][][] a;` | 3次元 | int の3次元配列 | ◎ |
| `int a[][][];` | 3次元 | 同上（C風） | △ |
| `int[][] a[];` | 3次元 | 同上（混在スタイル） | × 読みにくい |

> **動くけど書かない方がいいスタイル**：分けて書くパターン（`int[] a[];` のような形）は、文法的には正しくても **読み手を混乱させる** ので実務では避けましょう。

---

## 7. 「配列もインスタンス」という重要な事実

ここまでは「書き方」の話でしたが、もう一つ大事なポイントがあります。

> **配列は、内部的にはクラスから作られたインスタンス（オブジェクト）**

つまり、

```java
int[] array = new int[5];
```

の `new` は、`new String("hello")` などと同じく **インスタンスを生成している** のです。

このことから、配列について次の特徴が導けます。

| 特徴 | 説明 |
|------|------|
| 参照型である | 変数には「配列の本体への参照（住所）」が入る |
| `Object` を継承 | だから `toString()` や `hashCode()` を持っている |
| 配列の中に配列を入れられる | 要素として「他の配列への参照」を持てる → 多次元配列 |

---

## 8. 多次元配列が「配列の配列」である視覚イメージ

```java
int[][] a = new int[3][3];
```

これは「3個の int 配列を要素として持つ配列」を作っています。

```
a (1次元目)         (2次元目)
 ┌───┐
 │ ●─┼──→ [ 0, 0, 0 ]
 ├───┤
 │ ●─┼──→ [ 0, 0, 0 ]
 ├───┤
 │ ●─┼──→ [ 0, 0, 0 ]
 └───┘
```

`a` の各要素は「数値」ではなく「**別の配列への参照**」が入っています。これが多次元配列の正体です。

## 9. よくある質問

### Q1. `int[] a, b;` と `int a[], b;` は同じ？

**いいえ、違います！** ここは要注意ポイントです。

```java
int[] a, b;   // a も b も int の配列
int a[], b;   // a は int の配列、b はただの int
```

`[]` を型の後ろに書くと **両方の変数に効く**、変数名の後ろに書くと **その変数だけに効く** という違いがあります。これも「型の後ろ推奨」の理由のひとつです。

### Q2. 宣言と同時にサイズも決められる？

宣言だけならサイズは不要です。**`new` するときに初めてサイズが必要** になります。

```java
int[] a;            // 宣言のみ（OK）
int[] a = new int[5];  // 宣言と同時に5要素のインスタンス生成
// int[5] a;        // ← これは NG！宣言にサイズは書けない
```

## 10. ひとことでまとめ

> **`[]` の数 = 次元の数。位置は型の後ろでも変数名の後ろでもOK。  
> でも実務では「型の後ろにまとめて書く」のが読みやすくて安全。**

これが配列宣言の原則です。

# 配列インスタンスの生成の原則（初学者向け）

## 1. 一言でいうと

> **配列は「要素の型」と「長さ（または初期値）」が決まったときに、`new` または `{ … }` でヒープ上に作られるオブジェクト（インスタンス）です。**

変数宣言だけでは「箱」だけで、**実体を作るのがインスタンス生成**です。

---

## 2. 基本の形：`new 要素の型[長さ]`

```java
int[] a = new int[5];   // int が 5 個入る配列を生成
```

| 部分 | 意味 |
|------|------|
| `int[]` | 「int の配列」という型 |
| `new int[5]` | **長さ 5 の int 配列インスタンス** をヒープに作成 |
| `a` | そのインスタンスへの参照を入れる変数 |

**原則**：長さは **`new` の `[ ]` の中だけ** に書きます。変数宣言で `int[5] a` のように長さを書くことはできません。

---

## 3. 長さ 0 の配列も「正しいインスタンス」

```java
int[] empty = new int[0];
```

要素が 0 個でも **インスタンスとして成立** します（無効ではありません）。

---

## 4. 要素の初期値（生成直後）

`new` で作っただけでは、各要素には **型ごとのデフォルト値** が入ります。

| 要素の型 | 初期値 |
|----------|--------|
| 数値型（`byte`, `short`, `int`, `long`, `float`, `double`） | `0` / `0.0` |
| `char` | `'\u0000'` |
| `boolean` | `false` |
| 参照型（`String`, クラス, 別の配列など） | `null` |

---

## 5. 参照型の配列：`new` で「入れ物」だけ先に作る

```java
String[] s = new String[3];
```

ここでは **長さ 3 の「String の参照を並べた配列」** ができます。各要素は最初 `null` で、`new String("...")` などで後から代入できます。

---

## 6. 多次元配列：`new` の `[ ]` を次元の数だけ並べる

```java
int[][] m = new int[2][3];   // 2行×3列のイメージの「形」が固定
```

**原則**：左から順に、外側の次元 → 内側の次元の長さを指定します。

「ジャグ配列」（行ごとに長さが違う）にしたい場合は、例えば次のように **段階的に** 作ります。

```java
int[][] j = new int[2][];       // まず「行」だけ
j[0] = new int[3];
j[1] = new int[5];              // 行ごとに長さが違ってよい
```

---

## 7. 初期値リストと同時に生成する：`{ }` と匿名配列

### 宣言と同時に値を並べる（その場で長さが決まる）

```java
int[] a = { 10, 20, 30 };           // 長さ 3。new は省略される書き方
```

### すでにある式の位置で「型付きで」作る（匿名配列）

```java
someMethod(new int[] { 1, 2, 3 });  // メソッド引数などでよく使う
```

**原則**：`{ 1, 2, 3 }` だけを単独で書くと型が決まらないので、`new int[] { … }` のように **要素型を添える** ことが多いです。

---

## 8. よくある「原則」とミス

| 原則 | 間違いの例 |
|------|------------|
| 宣言時に長さは書かない | ~~`int[5] a;`~~ → NG |
| 長さは `new 型[n]` の `n` で指定 | `new int[5]` が正 |
| 配列の長さは生成後は変えられない | 伸ばしたいなら **別の配列を new** するなどが必要 |
| どちらか一方：`new int[size]` **または** `{ … }` で初期化 | 同じ宣言で両方をごちゃ混ぜにしない |

---

## 9. 全体の流れ（イメージ）

```
宣言          int[] arr;
                ↓
生成          arr = new int[5];   ← ここでヒープにインスタンスができる
                ↓
利用          arr[0] = 10;
```

---

## 10. ひとことまとめ

> **`new 要素型[長さ]` で長さ固定の配列オブジェクトを作る。**  
> **`{ … }` や `new 型[]{ … }` で、値から長さが決まる配列を作る。**  
> **長さは宣言ではなく「生成」のときに決め、後から変えられない。**

このセットが、Java での **配列インスタンス生成の原則**です。

# 配列の初期化で注意すべきポイント（初学者向け）

## 1. まずは全体像：配列の「生成 + 初期化 + 宣言 + 代入」の3つの書き方

配列を作るとき、**「インスタンス生成」「初期化」「変数宣言」「参照の代入」** の4ステップを一度にできる書き方が3種類あります。

| 書き方 | 例 | 特徴 |
|--------|------|------|
| **① 初期化子のみ** | `int[] a = {2, 3};` | 一番短い。**変数宣言と同時にしか使えない** |
| **② new + 要素数** | `int[] a = new int[2];` | 中身はデフォルト値（`0` など） |
| **③ new + 初期化子** | `int[] a = new int[]{2, 3};` | **要素数は書かない**（書くとエラー） |

この3つを混同しないことが、配列初期化の最大のポイントです。

---

## 2. 注意ポイント①：`new + 初期化子` のときは要素数を書かない

```java
int[] a = new int[]{2, 3};      // OK：要素数は省略
int[] a = new int[2]{2, 3};     // NG：コンパイルエラー
```

> **理由**：初期化子 `{2, 3}` を見れば「要素は2個」と **自動で分かる**。なのに `[2]` と書くと「人間が指定した数」と「初期化子の数」がケンカしてしまうため、Javaは **要素数を書くことを禁止** しています。

これが選択肢 A `int[] a = new int[2]{ 2, 3 };` が **誤り** の理由です。

```java
// 覚え方：new と {} を一緒に使うときは [] の中はカラ
int[] a = new int[]{2, 3};
//             ↑ ここは必ず空っぽ
```

---

## 3. 注意ポイント②：初期化子だけの書き方は「変数宣言と同時」だけ

```java
int[] a = {2, 3};          // OK：宣言と同時
int[] a;
a = {2, 3};                // NG：コンパイルエラー
```

これが選択肢 E `int e[]; e = {2,3};` が **誤り** の理由です。

> **理由**：`{2, 3}` だけでは **要素の型も次元数も決まらない**。  
> Javaは「変数の宣言」を見て「ああ、これは `int` の1次元配列なんだな」と判断するため、**宣言と切り離すと型が分からなくなる** のです。

### 解決策：分けて書きたいなら `new` を付ける

```java
int[] a;
a = new int[]{2, 3};       // OK：new int[] と書けば型情報がつく
```

これが選択肢 D が **正解** の理由です。

---

## 4. 注意ポイント③：要素ゼロでもOK

```java
int[] a = {};              // OK：要素ゼロの配列
int[] a = new int[0];      // OK：上と同じ意味
int[][] b = {};            // OK：2次元配列で要素ゼロ
int[][] c = new int[][]{}; // OK：上と同じ意味
```

「役には立たないけど文法的にはセーフ」というパターンです。  
これが選択肢 B と C が **正解** の理由です。

---

## 5. 注意ポイント④：多次元配列は「変数の次元」と「中身の次元」を一致させる

```java
int[][] a = new int[]{};    // NG：左は2次元、右は1次元 → エラー
int[][] a = new int[][]{};  // OK：両方とも2次元
int[][] a = {};             // OK：初期化子だけなら自動で2次元になる
```

> **重要**：初期化子だけ（`{}`）の書き方は、**変数の次元数を見て自動的に合わせてくれる** のです。これも「初期化子は宣言と同時じゃないとダメ」な理由のひとつです。

---

## 6. 設問の選択肢を一覧で整理

| 選択肢 | コード | 結果 | 理由 |
|--------|--------|------|------|
| A | `int[] a = new int[2]{2, 3};` | **エラー** | `new` + 初期化子のときに要素数を書いた |
| B | `int b[][] = {};` | **OK** | 初期化子だけ。要素ゼロの2次元配列ができる |
| C | `int[][] c = new int[][]{};` | **OK** | 次元数も合っていて、要素ゼロの2次元配列 |
| D | `int[] d; d = new int[]{2, 3};` | **OK** | `new int[]` を付けたので分けて書いてOK |
| E | `int e[]; e = {2,3};` | **エラー** | 初期化子だけは宣言と同時じゃないとダメ |

正解は **B、C、D** の3つです。

---

## 7. 「やっていい組み合わせ」早見表

| 書き方 | 宣言と同時 | 宣言と分離 |
|--------|:---:|:---:|
| `int[] a = {1, 2};` | ◎ | ✕ |
| `int[] a = new int[3];` | ◎ | ◎ (`a = new int[3];`) |
| `int[] a = new int[]{1, 2};` | ◎ | ◎ (`a = new int[]{1, 2};`) |
| `int[] a = new int[3]{1, 2};` | ✕ | ✕ |

---

## 8. なぜこんなルールがあるの？（理由を整理）

| ルール | 背景にある考え方 |
|--------|------------------|
| `new int[2]{1, 2}` がダメ | **要素数は初期化子から自動計算**するから、二重指定は禁止 |
| `{1, 2}` だけでは分けて書けない | `{}` 単体は **型情報を持たない**。変数宣言とセットで初めて型が決まる |
| 多次元の `{}` でも自動算出 | 初期化子は**変数の次元数に合わせて配列を作る**ので、変数宣言が必要 |

---

## 9. ひとことで覚える

> **「`new` と `{}` を両方使うときは `[要素数]` を書かない」  
> 「`{}` だけで初期化したいなら、変数宣言と **同じ行** に書く」**

この2つさえ守れば、配列初期化のコンパイルエラーは避けられます。

---

## 10. 安全に書くおすすめパターン

```java
// パターン1：宣言と同時に値を決めるとき
int[] a = {1, 2, 3};

// パターン2：あとで代入する／メソッド引数に渡すとき
int[] b;
b = new int[]{1, 2, 3};

// パターン3：サイズだけ決めて中身は後で入れるとき
int[] c = new int[5];
c[0] = 10;
```

この3パターンを使い分ければ、ほとんどの場面で困りません。

### 多次元配列に null が混ざると NullPointerException が起きる理由

ユーザー: @Chapter2_questions.md (759-780) でNu‖ PointerExceptionが発生するのは何故ですか？
似たような問題が出た時に間違えないためにはどうしたらよいですか？

アシスタント:
# なぜ `NullPointerException` が発生するのか（初学者向け解説）

## 1. まず正解の確認

このプログラムの実行結果は **E. 実行時に例外がスローされる** です。  
具体的には **`NullPointerException`（ヌルポインタ例外）** が発生します。

---

## 2. 配列の中身を絵で見てみよう

```java
String[][] array = { { "A", "B" }, null, { "C", "D", "E" } };
```

これは「2次元配列」ですが、**1次元目の真ん中に `null` が入っている** のがポイントです。

```
array (1次元目)        (2次元目)
 ┌─────┐
 │  ●──┼──→ [ "A", "B" ]          ← 長さ 2
 ├─────┤
 │ null │                          ← 参照先がない！
 ├─────┤
 │  ●──┼──→ [ "C", "D", "E" ]     ← 長さ 3
 └─────┘
```

> **`null` は「どこも指していない」という意味**。つまり「配列の参照を入れる箱だけはあるが、中身（参照先）が空っぽ」の状態です。

---

## 3. for-each ループの動きを1回ずつ追ってみよう

```java
for (String[] tmp : array) {
    total += tmp.length;
}
```

このループは、`array` の要素を1つずつ取り出して `tmp` に入れています。

| 回 | `tmp` に入る値 | `tmp.length` | 結果 |
|----|----------------|--------------|------|
| 1回目 | `{ "A", "B" }` への参照 | `2` | `total = 2` |
| 2回目 | **`null`** | **❌ 例外発生！** | **`NullPointerException`** |
| 3回目 | （実行されない） | - | - |

---

## 4. なぜ `null.length` で例外になるのか

`.length` という記法は、**「参照先のオブジェクトのプロパティを見る」** 操作です。

```java
tmp.length
 │    │
 │    └─ 「参照先の長さプロパティを取り出す」
 └────── 参照
```

ところが `tmp` が `null` だと、**そもそも参照先がない**ので、「長さを取り出す相手がいない」状態になります。

> Javaは「ない相手から何かを取ろうとした」瞬間に `NullPointerException` を投げます。これが今回起きていることです。

```
tmp ─→ ??? （null：行き先がない）
        ↓
    .length を取りに行こうとする
        ↓
    対象がいない！
        ↓
    NullPointerException
```

---

## 5. もし `null` がなかったら？

仮に2つ目の要素も普通の配列だったとします。

```java
String[][] array = { { "A", "B" }, { "X" }, { "C", "D", "E" } };
```

このときは、

- 1回目：`tmp.length` = 2
- 2回目：`tmp.length` = 1
- 3回目：`tmp.length` = 3
- **合計：6** が表示されます。

つまり今回の問題は **「`null` が1つ混ざっているだけで全体が壊れる」** ところに罠があるのです。

---

## 6. 似たような問題で間違えないための4つのチェックポイント

### チェック1：配列の初期化子の中に `null` が混ざっていないか？

```java
String[][] a = { { "A" }, null, { "B" } };
                          ↑ ここに注目！
```

**初期化子の中に裸の `null` があったら警戒**しましょう。多次元配列で出てきたら、ほぼ確実に「ループで `.length` か要素アクセスをしてエラー」のパターンです。

### チェック2：「参照を取り出す操作」をしていないか？

次のような操作は **すべて参照先が必要** です。`null` に対してやると例外になります。

| 操作 | 例 |
|------|------|
| プロパティ参照 | `obj.length`, `obj.size` |
| メソッド呼び出し | `obj.toString()`, `str.equals(...)` |
| 要素アクセス | `arr[0]` |
| 拡張 for で回す | `for (X x : arr)` |

### チェック3：`for-each` で取り出した変数も `null` になり得る

```java
for (String[] tmp : array) {  // tmp に null が入ることがある
    total += tmp.length;       // ← ここで NPE
}
```

**「ループ変数 = 必ず有効なオブジェクト」と思い込まない** ことが大切です。

### チェック4：「コンパイルは通るが実行時に死ぬ」パターンを覚える

`null` が混ざっていても **コンパイルエラーにはなりません**（型は合っているため）。  
だから選択肢に `D. コンパイルエラー` があっても、それは罠です。**`null` が絡むと `E. 実行時例外` を疑う** のが鉄則です。

---

## 7. 実際にミスを防ぐコードの書き方

実務でこういう配列を扱うときは、`null` チェックを入れるのが安全です。

```java
for (String[] tmp : array) {
    if (tmp == null) continue;     // null ならスキップ
    total += tmp.length;
}
```

または Java 8 以降なら：

```java
int total = Arrays.stream(array)
    .filter(Objects::nonNull)       // null を除外
    .mapToInt(a -> a.length)
    .sum();
```

問題を見たら、次の順番でチェックしましょう。

```
ステップ1：配列の初期化子に null がある？
            ↓ Yes
ステップ2：その配列を for-each や添字でアクセスしている？
            ↓ Yes
ステップ3：null になる要素に対して .length / .メソッド / [n] をしている？
            ↓ Yes
        → NullPointerException が答え！
```

| 例外名 | 起こる場面 | 今回の問題で起こる？ |
|--------|------------|---------------------|
| `NullPointerException` | `null` に対して `.` や `[]` を使った | **★これが正解** |
| `ArrayIndexOutOfBoundsException` | 配列の範囲外を `arr[100]` のように参照した | × |

この公式を覚えておけば、似た問題で迷うことはなくなります。

| `D` は `A` 型として扱える？ | OK（D → C → B → A） |

## 2. 配列の型互換ルールを覚える

### ルール①：**スーパー型の配列に、サブ型の配列の参照を入れられる**


```java

```

これは「配列は **共変（covariant）**」という性質によるものです。

> **覚え方**：「配列は寛容。スーパー型の入れ物には、サブ型を入れていい」

### 罠①：「`null` があるから例外！」と早とちりする

```java
// → ここで終わり。null には触っていない
```

### 罠②：「`Object[]` に代入できないのでは？」と疑う

すべてのクラスは `Object` を継承しているので、**配列は必ず `Object[]` に代入できます**。これは無条件にOKと覚えましょう。

### 罠③：「`A` はインタフェースだから配列にできないのでは？」と思う


「インタフェースのインスタンスは作れない」のは正しいですが、**「インタフェース型の配列」は作れる** ので注意。

### ArrayList の add メソッドの原則（末尾追加と挿入）

ユーザー: addメ ソッドの原則を分かりやすく正確に教えてください

アシスタント:
# `add` メソッドの原則（初学者向け解説）

`ArrayList`（リスト）の `add` メソッドには **2種類** あります。この違いを正確に理解することが、リスト操作の問題で間違えないためのカギです。

---

## 1. まず一言で

> **`add` には「末尾に追加」と「指定位置に挿入」の2種類があり、後者は範囲外の位置を指定すると例外が出る。**

---

## 2. `add` メソッドの2つの形

### 形①：`add(要素)` — 末尾に追加

```java
list.add("X");
```

| ポイント | 内容 |
|----------|------|
| 役割 | リストの **一番後ろ** に要素を追加 |
| 戻り値 | `boolean`（必ず `true`） |
| 失敗する？ | ほぼしない |

### 形②：`add(添字, 要素)` — 指定位置に挿入

```java
list.add(2, "X");
```

| ポイント | 内容 |
|----------|------|
| 役割 | 指定した **添字の位置に挿入**。元々その位置以降にあった要素は **1つずつ後ろにずれる** |
| 戻り値 | なし（`void`） |
| 失敗する？ | **添字が範囲外なら `IndexOutOfBoundsException`** |

---

## 3. 「指定位置に挿入」の動きを絵で見る

例：要素が3つあるリスト `[A, B, C]` に `list.add(1, "X")` を実行すると…

```
挿入前：   index:  0    1    2
                 ┌────┬────┬────┐
                 │ A  │ B  │ C  │
                 └────┴────┴────┘

挿入：    add(1, "X") → index 1 に "X" を挿入

挿入後：   index:  0    1    2    3
                 ┌────┬────┬────┬────┐
                 │ A  │ X  │ B  │ C  │   ← B と C が1つずつ後ろにずれた
                 └────┴────┴────┴────┘
```

> **重要**：「指定位置にあった要素を上書きする」のではなく、**「割り込み」して後ろを押し出す** イメージです。

---

## 4. 添字に指定できる範囲【最重要ルール】

`add(index, 要素)` の `index` に指定できるのは **`0 ～ list.size()`** までです。

```
size = 3 のリスト [A, B, C] の場合：

  指定可能な index：  0    1    2    3    ← 末尾の「次」までOK
                     ┌────┬────┬────┐
                     │ A  │ B  │ C  │
                     └────┴────┴────┘
                       ↑    ↑    ↑    ↑
                       OK   OK   OK   OK（末尾追加と同じ意味になる）

                                          ↑ index=4 はNG → 例外！
```

> **ポイント**：「`size` ちょうどはOK、`size` より大きいはNG」  
> つまり **「今ある要素の隙間と末尾の次まで」しか挿入できない**。

---

## 5. ここが落とし穴：`list.add(2, "B")` の例

```java
ArrayList<String> list = new ArrayList<>();
list.add("A");          // [A]   size=1
list.add(2, "B");       // ❌ index=2 は size(=1) より大きい → 例外！
```

リストには `"A"` が1つしかないのに、いきなり `index=2` を指定しています。  
このとき **`IndexOutOfBoundsException`** が発生します。

```
size = 1 のリスト：
  指定可能な index：  0    1    ← ここまで
                     ┌────┐
                     │ A  │
                     └────┘
                                  ↑ index=2 は範囲外！
```

設問39の答えは **E. 実行時に例外がスローされる** です。

---

## 6. 似ているけど違う「`set` メソッド」との比較

`add` と並んでよく出てくる `set` メソッドとの違いを必ず押さえましょう。

| メソッド | 動作 | 添字の有効範囲 | サイズの変化 |
|----------|------|----------------|--------------|
| `add(要素)` | **末尾に追加** | – | +1 |
| `add(index, 要素)` | **挿入**（後ろにずれる） | `0 ～ size` | +1 |
| `set(index, 要素)` | **上書き** | `0 ～ size-1` | 変わらない |

### 動きの違いを比較

リスト `[A, B, C]` に対して…

```
add(1, "X")  → [A, X, B, C]   ← 割り込み（要素が増える）
set(1, "X")  → [A, X, C]      ← 上書き（要素は増えない）
```

---

## 7. `add(index, 要素)` のよくある間違いパターン

### パターン①：空リストに `add(0, "X")`

```java
ArrayList<String> list = new ArrayList<>();
list.add(0, "X");   // OK！size=0 でも index=0 はOK
```

「サイズ0なのに index=0 ？」と不安になりますが、**「末尾の次」=「先頭」と一致する** のでセーフです。

### パターン②：`size` を超える添字を指定

```java
ArrayList<String> list = new ArrayList<>();
list.add("A");      // size=1
list.add(5, "X");   // ❌ size より大きい → IndexOutOfBoundsException
```

### パターン③：負の添字

```java
list.add(-1, "X");  // ❌ 負数も IndexOutOfBoundsException
```

---

## 8. 添字を扱うメソッド全体の有効範囲一覧

リスト操作系のメソッドは、添字の有効範囲が **2種類に分かれます**。

| 範囲 | メソッド | 理由 |
|------|----------|------|
| `0 ～ size-1` | `get`, `set`, `remove(int)` | **既存要素**を相手にするから |
| `0 ～ size` | `add(index, 要素)` | **隙間や末尾の次**にも挿入できるから |

> **覚え方**：「**入れる**ものだけ `size` ちょうどがOK、**取り出す/上書きする**ものは `size-1` まで」

---

## 9. `add` メソッドの原則まとめ

| 原則 | 内容 |
|------|------|
| 原則1 | `add(要素)` は **末尾追加**。失敗しない |
| 原則2 | `add(index, 要素)` は **割り込み挿入**。後ろがずれる |
| 原則3 | `add(index, 要素)` の有効範囲は **`0 ～ size`** |
| 原則4 | 範囲外なら **`IndexOutOfBoundsException`** |
| 原則5 | `add` で要素は **+1** される。`set` は **増えない** |

## 10. 問題を解くときの判定フロー

```
add(index, 要素) を見たら…
        │
        ▼
  「現在の size」を計算する
        │
        ▼
  index は 0 ～ size の範囲内？
        │
   ┌────┴────┐
   No        Yes
   │         │
   ▼         ▼
例外発生    挿入成功
        │
        ▼
  index 以降の要素が全部1つずつ後ろにずれる
```

## 11. 練習：リストの状態を頭の中で追ってみよう

正常な例（参考）：

```java
ArrayList<String> list = new ArrayList<>();
list.add("A");           // [A]
list.add("B");           // [A, B]
list.add("C");           // [A, B, C]
list.add(1, "X");        // [A, X, B, C]
list.add(4, "Y");        // [A, X, B, C, Y]   ← size と同じ index=4 はOK
```

各操作のあとに **「リストの状態を1行ずつメモする」** クセをつけると、こういう問題で必ず正解できるようになります。

> **「`add(要素)` は末尾、`add(index, 要素)` は割り込み挿入。

# 固定長リストの作成方法（2種類）の完全ガイド

Javaで「サイズが変わらないリスト」を作る方法は、主に2つあります。  
どちらも便利ですが、**特性が微妙に違う** ので、使い分けが大切です。

---

## 1. まずは一覧で比較

| | **`Arrays.asList()`** | **`List.of()`** |
|---|---|---|
| 提供元 | `java.util.Arrays` クラス | `java.util.List` インタフェース |
| 登場時期 | Java 1.2 から（古参） | Java 9 から（新しい） |
| サイズ変更 | できない（`add`/`remove` で例外） | できない |
| 要素の上書き | **できる**（`set` OK） | **できない**（`set` も例外） |
| `null` を入れられる | できる | **`NullPointerException`** |
| 元の配列との連動 | **連動する** | – |
| 用途 | 配列をリストっぽく扱いたい | 完全に変更不可な定数リスト |

> **キーワード**：  
> `Arrays.asList()` = **「固定サイズ」のみ**  
> `List.of()` = **「完全に変更不可（不変）」**

---

## 2. `Arrays.asList()` — 配列からリストを作る

### 基本の書き方

```java
import java.util.Arrays;
import java.util.List;

List<String> list = Arrays.asList("A", "B", "C");
```

### 配列から作るパターン

```java
String[] arr = { "A", "B", "C" };
List<String> list = Arrays.asList(arr);
```

### 何ができて、何ができないか

```java
List<String> list = Arrays.asList("A", "B", "C");

list.set(1, "X");      // OK：上書きはできる → [A, X, C]
list.get(0);           // OK：取得はできる
list.add("D");         // ❌ UnsupportedOperationException
list.remove(0);        // ❌ UnsupportedOperationException
```

### 注意ポイント①：元の配列と「連動」する

```java
String[] arr = { "A", "B", "C" };
List<String> list = Arrays.asList(arr);

arr[0] = "X";                  // 配列を変更すると…
System.out.println(list);      // → [X, B, C]   リストにも反映される！

list.set(1, "Y");              // リストを変更すると…
System.out.println(arr[1]);    // → Y          配列にも反映される！
```

> **理由**：`Arrays.asList()` は **配列の「ビュー（見た目）」を返している** だけで、内部では同じ配列を共有しています。

### 注意ポイント②：プリミティブ配列を渡すと意図しない動きに

```java
int[] arr = {1, 2, 3};
List<int[]> list = Arrays.asList(arr);   // 要素1つの List<int[]> になる！
System.out.println(list.size());          // → 1
```

`int[]` は「`int` の配列」自体が1つのオブジェクトなので、**「int配列を1つだけ持つリスト」** になってしまいます。これを避けるには `Integer[]` を使います。

```java
Integer[] arr = {1, 2, 3};
List<Integer> list = Arrays.asList(arr);  // → [1, 2, 3]   要素3つ
```

---

## 3. `List.of()` — 完全に変更不可なリストを作る

### 基本の書き方

```java
import java.util.List;

List<String> list = List.of("A", "B", "C");
```

`Arrays.asList()` と書き方はそっくりですが、**動きが違います**。

### 何ができて、何ができないか

```java
List<String> list = List.of("A", "B", "C");

list.get(0);          // OK：取得はできる
list.set(1, "X");     // ❌ UnsupportedOperationException ← ここが違う！
list.add("D");        // ❌ UnsupportedOperationException
list.remove(0);       // ❌ UnsupportedOperationException
```

> **`List.of()` は「読むだけ」のリスト**。一度作ったら絶対に変えられません（**イミュータブル＝不変**）。

### 注意ポイント①：`null` を入れられない

```java
List<String> list = List.of("A", null, "C");  // ❌ NullPointerException
```

`List.of()` は **`null` 要素を許可しません**。データの一部に `null` が混ざる可能性があるなら、`Arrays.asList()` を使うか、別の方法を検討する必要があります。

### 注意ポイント②：配列とは連動しない

```java
String[] arr = { "A", "B", "C" };
List<String> list = List.of(arr);

arr[0] = "X";
System.out.println(list);   // → [A, B, C]   元のままで連動しない
```

`List.of()` は **要素を内部にコピーして保持** するため、元の配列を変更しても影響しません。

## 4. 「固定長」の意味を正しく理解する

「固定長リスト」と一口に言っても、**2段階の固定** があります。

```
段階1：サイズが固定（要素数が増減しない）
段階2：要素も固定（中身も書き換えられない）
```

| メソッド | 段階1（サイズ固定） | 段階2（要素固定） |
|----------|:---:|:---:|
| `Arrays.asList()` | OK | NG |
| `List.of()` | OK | OK |

## 6. ありがちな勘違い

### 勘違い①：`new ArrayList<>(3)` で固定長になる？

```java
ArrayList<Integer> list = new ArrayList<>(3);
list.add(1);
list.add(2);
list.add(3);
list.add(4);  // 普通に追加できる！
```

> `new ArrayList<>(3)` の `3` は **「初期容量」** であって、**最大サイズではありません**。サイズを超えると内部で自動的に拡張されます。これは「固定長」ではありません。

### 勘違い②：`List.of()` は `add` できる？

```java
List<Integer> list = List.of(1, 2, 3);
list.add(4);   // ❌ UnsupportedOperationException
```

「リスト」と聞くと `add` できそうな気がしますが、**`List.of()` は読み取り専用** です。

### 勘違い③：`Arrays.asList()` は `ArrayList` を返す？

実は **返ってくるのは `java.util.Arrays$ArrayList`**（内部クラス）であり、よく使う `java.util.ArrayList` とは別物です。だから `add` ができません。

### String の不変性と replaceAll の戻り値（変更前の文字列が出力される理由）

です。
オブジェク トは、何らかのデータを内部に持 つています。このとき、一度セッ
トしたフィール ドの値を、後から変更できるオブジェク トと、変更できない
オブジェク トがあります。変更できるオブジェク トのことを「mutable(可 変)
なオブジェク ト」、変更できないオブジェク トのことを「immutable(不変)
なオブジェク ト」と呼びます。
インスタンスヘの参照をほかのメソッ ドの引数に渡すと、そのメソッ ド内で
インスタンスが持つデータが不適切に変更されて しまう可能性があ ります。

クローンヘの参照を渡すという方法があ ります。 しか し、メソッ ド呼び出 し

更できないように定義されたオブジェク トを使 つて、データが不適切に変更
されるのを防ざます。このようなimmutableな オブジエク トを定義するには、
次のようにします。
すべてのフィール ドをprivateで 修飾する
オブジェク ト内部の状態を変更可能なメソ ッ ドは提供 しなしヽ(た とえば
setterメ ソッドを提供 しない)
クラスをfina:で 宣言 し、メソッ ドがオーバーライ ドされないことを保証す
る (サ ブクラスからの変更を防ぐ)
内部に可変オブジェク トを保持 している場合、そのオブジェク トを外部に
提供 しない (た とえばgetterメ ソッドを提供 しない)
次のクラスは、immutableな クラスの例です。このクラスは1つだけprivateな
フィール ドを持ちますが、コンス トラクタで初期化 した後は、このフィール

アシスタント:
# 「変更前の文字列が出力される」とはどういうことか

このトピックは Java 初学者がほぼ全員つまずく **「String は不変（immutable）」** の話です。コードと一緒に、何が起きているのかを順番に追っていきましょう。

---

## 1. まず対象のコードを確認

```java
public class Main {
    public static void main(String[] args) {
        String str = "hoge, world.";
        hello(str);                          // ← ここで何が起きる？
        System.out.println(str);             // ← 表示は？
    }
    private static void hello(String msg) {
        msg.replaceAll("hoge", "hello");     // ← 戻り値を捨てている！
    }
}
```

実行結果は **`hoge, world.`**（＝ 変更前のまま）です。  
「`replaceAll` で書き換えたはずなのに、なぜ変わらないの？」という疑問の答えを順に見ていきます。

---

## 2. キーワードは「String は不変（immutable）」

> **「不変オブジェクト」とは、一度作ったら、その中身を絶対に変えられないオブジェクトのこと。**

`String` はその代表選手です。

```java
String s = "hoge";
// この "hoge" の中身を直接 "hello" に書き換えることは絶対にできない
```

**メモリ上に作られた `"hoge"` という文字列は、その瞬間から永遠に `"hoge"` のまま** です。

---

## 3. では `replaceAll` は何をしている？

「文字列を置き換えるメソッド」と聞くと、元の文字列を変更しているように見えます。  
でも実際は違います。

> **`replaceAll` は、置き換えた結果を持つ「新しい String インスタンス」を作って、その参照を返している。元の文字列は手付かず。**

絵で見るとこうです。

```
元：  ┌──────────────┐
      │ "hoge, world." │   ← これは手をつけない
      └──────────────┘
            ↓ replaceAll("hoge", "hello") を実行

新： ┌────────────────┐
      │ "hello, world." │   ← 新しい String が生まれる
      └────────────────┘
            ↓
        この新しいインスタンスへの「参照」が戻り値として返る
```

**元の `"hoge, world."` には何の変化もありません。** 新しい文字列が **別途生まれているだけ** なのです。

---

## 4. 問題のコードで何が起きているか（ステップ実行）

### ステップ1：`main` で文字列を作る

```java
String str = "hoge, world.";
```

```
str ──→ ┌───────────────┐
        │ "hoge, world." │
        └───────────────┘
```

### ステップ2：`hello(str)` を呼び出す

`str` の **参照（住所）が `msg` にコピー** されます。

```
str ──→ ┌───────────────┐ ←── msg
        │ "hoge, world." │
        └───────────────┘
```

> 重要：`str` と `msg` は **同じ文字列を指している** だけで、別々の変数です。

### ステップ3：`msg.replaceAll("hoge", "hello")` を実行

```java
msg.replaceAll("hoge", "hello");   // 戻り値を変数に受け取っていない！
```

新しい文字列が作られます。

```
str ──→ ┌───────────────┐ ←── msg
        │ "hoge, world." │
        └───────────────┘

         ┌────────────────┐
         │ "hello, world." │  ← 新しく生まれたが、誰も参照していない
         └────────────────┘
                 ↓
           ゴミ（GCの回収対象）
```

> **「戻り値を受け取らずに捨てている」** のがこのコードの問題点。  
> 新しくできた `"hello, world."` を指す変数がどこにもないので、ただのゴミになります。

### ステップ4：`hello` メソッドが終わって `main` に戻る

```
str ──→ ┌───────────────┐
        │ "hoge, world." │   ← 元のまま！
        └───────────────┘
```

### ステップ5：`System.out.println(str)`

`str` が指している先は **依然として `"hoge, world."`**。  
だから出力は **`hoge, world.`** になります。

---

## 5. 「変更前の文字列が出力される」の意味

> **`replaceAll` は元の文字列を一切変更していない。  
> だから `str` が指している文字列は、メソッド呼び出し前と完全に同じ。  
> その結果、`println` で表示されるのも変わらず元の `"hoge, world."` になる。**

これが「変更前の文字列が出力される」という言葉の意味です。

---

## 6. 正しく置き換えた結果を表示するには？

`replaceAll` の **戻り値を必ず受け取る** 必要があります。

### パターン①：新しい変数に代入する

```java
private static void hello(String msg) {
    String result = msg.replaceAll("hoge", "hello");
    System.out.println(result);   // → "hello, world."
}
```

### パターン②：元の変数に再代入する

```java
private static void hello(String msg) {
    msg = msg.replaceAll("hoge", "hello");  // msg の参照先を新しい文字列に向ける
    System.out.println(msg);                // → "hello, world."
}
```

ただし **これでも `main` の `str` は変わりません**（参照渡しではないため）。`main` に結果を反映したい場合は…

### パターン③：戻り値を返して呼び出し元に渡す

```java
public static void main(String[] args) {
    String str = "hoge, world.";
    str = hello(str);                  // 戻り値を受け取る
    System.out.println(str);           // → "hello, world."
}
private static String hello(String msg) {
    return msg.replaceAll("hoge", "hello");
}
```

---

## 7. なぜ Java は String を「不変」にしたのか

「不便」に見える `String` の不変性ですが、ちゃんと理由があります。

| メリット | 説明 |
|---------|------|
| **安全性** | 一度作った文字列を勝手に変えられないので、別のスレッドや別のメソッドで「気づかぬうちに改ざん」される心配がない |
| **String Pool** | 同じ文字列を共有して使い回せる（メモリ節約） |
| **ハッシュキーに最適** | `HashMap` のキーに使ったとき、後から中身が変わってバグになる心配がない |
| **キャッシュが効く** | ハッシュ値などを内部に保存しておける |

> 不変性は「変更を防ぐ」というより、**「予期せぬ変更からプログラム全体を守る盾」** なのです。

---

## 8. 不変性を持つ Java の代表的なクラス

| クラス | 説明 |
|--------|------|
| `String` | 文字列。`replace`, `substring` など全て新しいインスタンスを返す |
| `Integer`, `Long`, `Double` などのラッパー | 数値の中身を変更できない |
| `LocalDate`, `LocalDateTime`（Java 8〜） | 日付。`plusDays` なども新しい日付を返す |
| `java.io.File` | ファイルパス。一度作ったら変更不可 |

これらに対して **「メソッドを呼んだだけで元のオブジェクトが変わる」と勘違いしない** よう注意しましょう。

---

## 9. 「不変オブジェクト」あるあるミスのパターン集

```java
// ① replace 系
String s = "hello";
s.replace("h", "H");
System.out.println(s);   // → hello （変わらない！）

// ② trim
String s = "  hello  ";
s.trim();
System.out.println(s);   // → "  hello  " （変わらない！）

// ③ toUpperCase
String s = "hello";
s.toUpperCase();
System.out.println(s);   // → hello （変わらない！）

// ④ concat
String s = "hello";
s.concat(" world");
System.out.println(s);   // → hello （変わらない！）
```

すべて共通して、**「戻り値を受け取らないと意味がない」** のです。  
正しくは：

```java
s = s.replace("h", "H");
s = s.trim();
s = s.toUpperCase();
s = s.concat(" world");
```

```

              ↓
ステップ2：その戻り値を変数に受け取っている？
              ↓
   ┌──────────┴──────────┐
   No                    Yes
   │                     │
   ▼                     ▼
変化なし！           新しい文字列が使える
```

## 11. ひとことで覚える

> **「String は不変。`replaceAll` は元を変えず、新しい文字列を返すだけ。  
> 戻り値を受け取らなければ、何もしていないのと同じ。」**

つまり今回の解説の **「コンソールに出力されるのは、変更前の文字列です」** は、

> **「`replaceAll` の結果を捨てているので、元の `"hoge, world."` がそのまま残っており、それが表示される」**

という意味だったのです。

---

## 12. 学習用：`String` のメソッドは全て「新しい String を返す」

| メソッド | 戻り値 |
|----------|--------|
| `replace`, `replaceAll` | 置換後の新しい String |
| `trim`, `strip` | 前後の空白を除いた新しい String |
| `toUpperCase`, `toLowerCase` | 大小変換した新しい String |
| `substring` | 部分文字列の新しい String |
| `concat` | 結合した新しい String |
| `+` 演算子 | 結合した新しい String |

> **「String 系メソッドを呼ぶ ＝ 新しい文字列を返す」と機械的に覚える** のが、こういう問題で間違えないコツです。
